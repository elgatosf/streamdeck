# Neo Infobar

Neo Infobar actions are display-only actions that use the layout system to render information on the Infobar found on Stream Deck Neo. Unlike key and dial actions, they do not receive user interaction events. They can, however, display dynamic information and respond to updates from your plugin.

<Tip>
	Neo Infobar actions require Stream Deck 7.6 or later—be sure to update your manifest's
	[`Software.MinimumVersion`](../references/manifest.mdx#software-minimumversion) when adding support for them.
</Tip>

## Registering Actions

Neo Infobar actions are registered in the same way as other actions, in the manifest. Define the action's metadata in the manifest, including `Neo` in the [`Controllers`](../references/manifest.mdx#action-controllers) property:

```json title="Defining a Neo Infobar action in the manifest"
{
	"Actions": [
		{
			"Name": "Neo Infobar Example Action",
			"UUID": "com.elgato.example.neo-infobar",
			"Controllers": ["Neo"] // [!code highlight]
		}
	]
}
```

Then implement the action as a class that inherits from `SingletonAction`, and register it in the application-layer entry file, as described in [Registering Actions](./actions.mdx#registering-actions).

## Layouts

Layouts are the rendering engine used to display information on a Stream Deck Neo Infobar. Layouts on Stream Deck Neo are <Dimensions width="232" height="50" />, and are composed of [layout items](../references/layouts.mdx) whose values can be updated at runtime to display dynamic information.

The following is an example of a layout that renders the title, with an image on either side:

{/* prettier-ignore */}
```jsonc title="Layout JSON file for a Neo Infobar action"
{
    "$schema": "https://schemas.elgato.com/streamdeck/plugins/layout.json",
    "id": "neo",
    "controller": "Neo",
    "items": [
        {
            "type": "pixmap",
            "key": "leading",
            "rect": [10, 15, 20, 20]
        },
        {
            "key": "title",
            "type": "text",
            "rect": [40, 15, 152, 20],
            "font": {
                "size": 15
            }
        },
        {
            "key": "trailing",
            "type": "pixmap",
            "rect": [202, 15, 20, 20]
        }
    ]
}
```

<Image
	src="../assets/layout-neo-infobar.png"
	alt="Stream Deck Neo Infobar layout with the title in the middle, and an image either side."
/>

In summary, layout items within a layout:

- Must have a unique `key`.
- Must have their `type` and `rect` defined.
- Must not overlap with other items in the layout, see [`zOrder`](../references/layouts.mdx#bar-zorder).
- Must be within the bounds of the layout.

<Warning>

Layouts will not render when:

- A layout item is outside the allotted bounds of the layout.
- Layout items overlap on the same `zOrder`.

For assistance with debugging layouts, try using the CLI tool's [`validate`](../../docs/streamdeck/cli/commands/validate.mdx) command, or referring to the [Stream Deck app logs](./logging.mdx#stream-deck-logs).

</Warning>

### Setting the Layout

The layout of a Neo Infobar action instance is set using the [`setFeedbackLayout`](#setfeedbacklayout) function, and must be set every time the [`onWillAppear`](#onwillappear) event occurs, for example:

```ts title="Action class updating its layout to a custom layout file"
import { action, SingletonAction, WillAppearEvent } from "@elgato/streamdeck";

@action({ UUID: "com.elgato.example.neo-infobar" })
export class NeoInfobarExampleAction extends SingletonAction {
	/**
	 * Occurs when the action appears.
	 */
	override async onWillAppear(ev: WillAppearEvent): Promise<void> {
		if (ev.action.isNeoInfobar()) {
			// Set the layout.
			await ev.action.setFeedbackLayout("layout.json"); // [!code highlight]
		}
	}
}
```

### Updating Layout Items

Layout items can be updated at runtime using the [`setFeedback`](#setfeedback) function, with items referenced by their `key`. All properties, with the exception of their `rect` can be updated; in addition, the `value` of a layout item can be updated implicitly or explicitly.

The following example demonstrates updating the `value` of the `title` item implicitly:

```ts title="Updating the title implicitly"
import { action, SingletonAction, WillAppearEvent } from "@elgato/streamdeck";

@action({ UUID: "com.elgato.example.neo-infobar" })
export class NeoInfobarExampleAction extends SingletonAction {
	/**
	 * Occurs when the action appears.
	 */
	override async onWillAppear(ev: WillAppearEvent): Promise<void> {
		if (ev.action.isNeoInfobar()) {
			// Set the layout.
			await ev.action.setFeedbackLayout("layout.json");

			// Set the layout item values.
			await ev.action.setFeedback({
				title: "Hello world", // [!code highlight]
			});
		}
	}
}
```

The following example demonstrates updating the `value` of the `title` item explicitly; this is useful when more than one property needs to be updated on an item:

```ts title="Updating the title explicitly"
import { action, SingletonAction, WillAppearEvent } from "@elgato/streamdeck";

@action({ UUID: "com.elgato.example.neo-infobar" })
export class NeoInfobarExampleAction extends SingletonAction {
	/**
	 * Occurs when the action appears.
	 */
	override async onWillAppear(ev: WillAppearEvent): Promise<void> {
		if (ev.action.isNeoInfobar()) {
			// Set the layout.
			await ev.action.setFeedbackLayout("layout.json");

			// Set the layout item values.
			await ev.action.setFeedback({
				title: {
					opacity: 0.5,
					color: "#FF0000",
					value: "Hello world", // [!code highlight]
				},
			});
		}
	}
}
```
